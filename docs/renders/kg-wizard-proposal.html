The Install Wizard

Form factor, both phases, and every question — screen by screen, with what each one validates and why it earns its place.

0 · Form factor

My recommendation — and the honest alternatives

The question splits on one observation: the wizard's real work is OAuth flows and credential entry, and OAuth lives in the browser by design — Google actively blocks embedded webviews. So the browser is non-negotiable for phase 2; the only open question is what runs the first ten minutes, before a server exists.

ADR-0013 — agreed 2026-08-01 Two browser phases. Zero native apps.
Proposed
Phase 1 — the launcher: npx kb@latest starts a tiny local web UI (localhost) in your browser; it collects the pre-server answers, then provisions and deploys with live progress. Phase 2 — the wizard: served by the system itself at your real domain, first-boot setup mode, one-time admin URL. Same React components in both; the CLI does what CLIs are native to (SSH, provisioning), the browser does what browsers are native to (OAuth, forms, live status).
Alt A
Native Mac installer app — signing + notarization + an update pipeline (and CA$130/yr developer account) for ten minutes of use; excludes non-Mac installers; and OAuth-in-webview is blocked by Google anyway, so it would bounce to the browser regardless. The mini itself needs only an enroll script — a menu-bar status item can come later, and it's not an installer.
Alt B
Hosted click-to-deploy (a site of ours that provisions for you) — smoothest possible UX, but we'd hold users' Hetzner tokens on our server and run always-on infrastructure; the sovereignty story breaks on day one. A legitimate future business; the wrong v1.
Alt C
Pure CLI prompts — fine for us, hostile for the audience this is for; and phase 2 still needs the browser, so a TUI just duplicates the wizard in a worse medium.
0
Native apps to build, sign, notarize, or update — the browser and the CLI each do what they're native to
19
Questions total across both phases — 12 are paste-a-value, 5 are choices with safe defaults, 2 are free text
✓ → ∞

What we never ask — every unasked question is a support ticket that never happens

  • Server size, Postgres anything, ports, TLS details, backup schedule — derived or fixed, shown not asked.
  • Embedding model, extractor thresholds, queue settings — config with consequences, not setup questions.
  • Bot display name, region (beyond one link), currency of stored data — defaults with a settings page.
  • Anything twice. If the launcher learned it, the wizard knows it.
Resume, re-run, and team members Close the browser at any step — state lives in the database; the checklist resumes where you left it. Every card reappears in Settings → Connections afterward, so the wizard is never the last chance. Teammates never see this wizard: they get an invite link that runs exactly one step — their own Google consent.
